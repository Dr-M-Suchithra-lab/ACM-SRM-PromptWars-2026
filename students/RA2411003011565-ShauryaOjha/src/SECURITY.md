# Security

FairShift holds pay, attendance and safety records for low-wage workers, many of whom share phones. It is built so that a worker can never see another worker's data, a supervisor can never see beyond their organisation, and anonymous feedback cannot be traced back to a person.

## Reporting a problem

Please open a private security advisory on the repository, or email the maintainer. Do not file a public issue for a vulnerability.

## Threat model and controls

| Threat                                             | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Where                                                                                                   |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| Leaked secrets                                     | No secret is in the repo. `.env*` is git-ignored except `.env.example`, which holds names only. Keys live in the host's environment variables. The server env is parsed and validated once, and errors never echo values.                                                                                                                                                                                                                                                                                          | `.gitignore`, `src/server/env.ts`                                                                       |
| Session forgery or tampering                       | HMAC-SHA256 signed, `httpOnly`, `sameSite=lax`, `secure` cookies with a 7-day expiry. Signatures are compared with `timingSafeEqual`. Production refuses to start a request without `SESSION_SECRET`.                                                                                                                                                                                                                                                                                                              | `src/server/auth/session.ts`                                                                            |
| Brute-forcing a PIN or password                    | PINs and passwords are scrypt-hashed. Logins allow 20 tries per IP per minute, and an account locks after 5 failures in 15 minutes. Wrong phone, wrong PIN and inactive account all return the same error.                                                                                                                                                                                                                                                                                                         | `src/server/auth/{password,rateLimit}.ts`                                                               |
| Guessing the gate QR code                          | The code rotates every 60 s (TOTP-style HMAC) and accepts ±1 window. Check-in is limited to 6 tries a minute per worker.                                                                                                                                                                                                                                                                                                                                                                                           | `src/server/domain/qrCode.ts`, `app/w/actions.ts`                                                       |
| Reading another worker's records (IDOR)            | Every action derives the worker from the signed session, never from input. Shift, hazard and feedback writes re-check that the site belongs to the worker's organisation.                                                                                                                                                                                                                                                                                                                                          | `app/w/actions.ts`, `src/server/services/workerService.ts`                                              |
| A supervisor reaching another organisation         | The session carries the signed list of permitted organisations. The sector switcher only honours those. Hazard actions re-check the hazard's organisation.                                                                                                                                                                                                                                                                                                                                                         | `src/server/auth/guard.ts`, `app/admin/_lib/context.ts`                                                 |
| De-anonymising feedback                            | Feedback stores no worker id. One answer per person a week is enforced by a separate ballot: an HMAC of worker, team and week under a server key, claimed atomically and never stored beside the answer. Team results stay hidden until 3 people answer (k-anonymity). Names on the roster, phone numbers and emails are scrubbed from comments, including Hindi and Tamil names.                                                                                                                                  | `src/server/domain/anonymity.ts`                                                                        |
| Injection through input                            | Every Server Action parses its input with zod first: ISO timestamps, bounded lengths, id character sets and enums. | Forged offline replays                             | A queued action's capture time must be within the last 24 h and not more than 2 minutes ahead. The QR code is verified at the capture time. Client ids make a replay idempotent.                                                                                                                                                                                                                                                                                                                                   | `src/server/domain/offline.ts`                                                                          |
| Prompt injection against the AI assistant          | The assistant's (Urima's) tools are read-only and have **no parameters**. Each is bound on the server to the signed-in worker, or to the admin's permitted sector, so no text in a question can widen what is read. Hazard text is fenced as data. AI may raise a hazard's severity, never lower it.                                                                                                                                                                                                               | `src/server/assistant/*`, `src/server/ai/gemini.ts`                                                     |
| AI cost abuse                                      | The assistant allows 8 questions a minute per worker, a 500-character question, 8 turns of history, 3 tool rounds and a 12 s timeout. A circuit breaker stops calling Gemini after a 429.                                                                                                                                                                                                                                                                                                                          | `app/w/actions.ts`, `src/server/ai/client.ts`                                                           |

| Closing a hazard on paper only                     | A named report resolved by a supervisor waits for the reporter. Someone else's report looks the same as a missing one.                                                                                                                                                                                                                                                                                                 | `src/server/domain/hazardClosure.ts`, `workerService.giveHazardVerdict`                                 |
| Unmasking an anonymous hazard reporter             | An anonymous report keeps its time only to the IST hour (rounded down, so the response deadline only gets stricter), so it cannot be lined up against the gate log or CCTV. It stores no reporter id.                                                                                                                                                                                                                                                                                                              | `src/server/domain/hazardSignals.ts`, `workerService.reportHazard`                                      |
| A serious hazard filed as "low"                    | Danger words in English, Hindi and Tamil ("live wire", "बिजली", "மின்") raise the severity before the AI runs, so a model that is off, rate-limited or talked round by the text cannot leave it on a 72-hour clock. Words only ever raise a rating.                                                                                                                                                                                                                                                                | `src/server/domain/hazardSignals.ts`                                                                    |
| Changing pay rules to cut earned pay               | Overtime rules are versioned. A change must stay within the law (overtime after at most 8 h a day / 48 h a week, at 2× to 3×), start on one of the next four Mondays, carry a written reason and the admin's name. Every week is paid under the rules in force that week, so a change can never reach back. The server re-checks after zod.                                                                                                                                                                        | `src/server/domain/payRules.ts`, `services/adminPay.ts`                                                 |
| Closing a pay query without paying                 | Only the worker who raised a pay query can mark it settled, and only after an answer; "not yet" reopens it with a 24-hour deadline. The payslip figure on it is computed on the server, never sent by the client. Another worker's or another organisation's query looks the same as a missing one. Raising is limited to 5 an hour, answers and rule changes to 20 a minute per admin.                                                                                                                            | `src/server/domain/payQuery.ts`, `workerService.{raisePayQuery,givePayVerdict}`, `services/adminPay.ts` |

| A slow or hostile weather service                  | The weather response is parsed with zod and range-checked, the call has a 3 s timeout, failures are cached for 30 minutes, and on any failure the heat card is simply not shown.                                                                                                                                                                                                                                                                                                                                   | `src/server/weather.ts`                                                                                 |
| Paying the wrong amount, or paying a month twice   | The UPI link's amount is the payslip computed on the server; the form sends only the worker, month and UTR, and the amount is worked out again when it is recorded. One record per worker and month (the id is the key, so a second write fails atomically). Only last month and this month, only a worker at the session's own site, a 12-digit UTR, 20 a minute per admin. The UPI ID must match the NPCI handle@bank form, so a crafted one cannot add parameters to the link.                                  | `src/server/domain/wagePayment.ts`, `services/adminPay.ts`                                              |
| The assistant filing a report by itself            | Urima only drafts. Detection is rule-based, no model is called for a draft, and nothing is written until the worker presses Send, which goes through the same `reportHazardAction` (session, zod, rate limit, severity floor) as the form.                                                                                                                                                                                                                                                                         | `src/server/assistant/drafts.ts`, `src/components/worker/AskDraft.tsx`                                  |
| An employer editing hours after the fact           | At check-out the shift's worker, site and times are signed with HMAC-SHA256 under a key derived from `SESSION_SECRET` (a separate purpose label). The receipt is a public link: the check page compares it with the record as it stands and shows unchanged, changed (which fields) or deleted. A labour-office letter carries a signed period total (shifts and minutes), so a shift removed or added later also shows. Signatures are compared with `timingSafeEqual`; tokens over 2,000 characters are refused. |
| What the public check page reveals                 | Only the worker's first name, the site name and the shift times. No phone, pay or worker id is shown, and the page sets `noindex`.                                                                                                                                                                                                                                                                                                                                                                                 |
| Clickjacking, sniffing and cross-origin leaks      | `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, HSTS (2 years, preload), COOP and CORP `same-origin`, a strict `Referrer-Policy` and a `Permissions-Policy` that allows only the mic and location.                                                                                                                                                                                                                                                                                                   | `next.config.ts`                                                                                        |
| Data left on a shared phone                        | Logout clears the cached worker pages. The service worker never caches `/w/login` or `/admin`. The offline outbox is bound to a worker id and only syncs for that worker. The assistant conversation is never stored.                                                                                                                                                                                                                                                                                              | `public/sw.js`, `src/lib/offline/*`                                                                     |

## Known trade-offs

- **`script-src 'unsafe-inline'`.** The app uses Partial Prerendering (Cache Components), and the Next.js docs state that nonce-based CSP is incompatible with it: the static shell is built before any request, so it cannot carry a per-request nonce. Our mitigations:
  - React escapes all rendered text.
  - The only raw HTML is the kiosk QR code, an SVG the `qrcode` library builds from server values.
  - `connect-src`, `form-action`, `base-uri` and `frame-ancestors` are all locked to `'self'` or `'none'`.
- **Receipts depend on `SESSION_SECRET`.** Rotating it makes every earlier receipt read as "not valid". A receipt proves what FairShift recorded, not what happened on site, and the server holds the key, so it protects the worker against later edits by the employer, not against the server operator.
- **The rate limiter is in memory, per server instance.** On a serverless host each warm instance counts on its own, so the effective cap is a multiple of the configured one. Login also has a per-account lockout, and PINs are scrypt-hashed. For a large deployment, move the counters to Redis.
- **Data sent to Gemini.** Payslip numbers, hazard text and, for supervisors, worker names and quit-risk reasons are sent to the Gemini API when `GEMINI_API_KEY` is set. Without a key, nothing leaves the server, and every feature still works on rule-based answers.
