## Changes and justification

1. Preserve the exact SELECT authorization predicates on `members_read`, `shift_read` and `dispute_read`, replacing their direct `auth.uid()` calls with `(select auth.uid())`. This addresses the three advisor warnings without widening roles, ownership or organization access.
2. Add six covering indexes for the advisor's six unindexed foreign keys: dispute-event dispute/time and organization/time; organization sector; dispute shift/organization/worker; policy-event organization/time; shift organization/worker/time.
3. Retain every existing index, including the two currently reported unused indexes. Current low usage is not evidence that a useful shift/history index should be removed.
4. Do not change schemas, business records, RPC permissions or private-table RLS. The three private tables intentionally have RLS with no policies and no application SELECT grants. This is deny-all behavior, not a reason to add permissive policies.

References: [Supabase RLS performance guidance](https://supabase.com/docs/guides/database/postgres/row-level-security#call-functions-with-select), [foreign-key index advisor](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys).

## Risks and application approach

Applying ALTER POLICY briefly locks policy metadata. Ordinary index creation can briefly block concurrent writes and consumes storage; the current synthetic tables are small. The migration sets a 3-second lock timeout and a 30-second statement timeout so an unavailable lock or unexpectedly slow build fails instead of waiting indefinitely. Apply the entire migration transactionally through the migration integration, in an owner-approved window. For a large future production dataset, prepare a separate concurrently-built index rollout rather than silently changing this plan.

The SQL was reviewed against the actual hosted policies, constraints and indexes. It has not been executed against the hosted database, even as a trial. After approval and application, rerun security/performance advisors, SELECT-only RLS checks and the synthetic authentication/workflow checks. Confirm all three RLS warnings and six missing-index findings are resolved.

## Rollback

If application fails in its transaction, PostgreSQL rolls back the transaction. If an applied migration must be reversed, use a separately reviewed compensating migration restoring the following original predicates and removing only the six indexes introduced above. Do not delete records or disable RLS.

```sql
alter policy members_read on public.organization_members
  using (user_id = auth.uid() or private.is_member(organization_id, true));
alter policy shift_read on public.shifts
  using (private.is_member(organization_id)
    and (worker_id = auth.uid() or private.is_member(organization_id, true)));
alter policy dispute_read on public.pay_disputes
  using (private.is_member(organization_id)
    and (worker_id = auth.uid() or private.is_member(organization_id, true)));
-- Only after verifying these indexes were created by this migration:
drop index public.events_dispute_time;
drop index public.events_org_time;
drop index public.organizations_sector;
drop index public.disputes_shift_membership;
drop index public.policy_events_org_time;
drop index public.shifts_org_worker_time;
```

This rollback is a reviewable plan, not executed SQL.
